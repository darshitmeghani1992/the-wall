## Purpose

The current PostgreSQL SQL suite (including 73 Shared-Wall INSERT RETURNING) uses `SET ROLE authenticated` and synthetic `auth.uid()` test fixtures. That is valuable **database contract** evidence but does not verify real HTTP JWT authorization. This opt-in Node 22 harness independently targets only **staging** `ewintxgdxdvschiqodkq`, checks three truly distinct authenticated user identities via `GET /auth/v1/user`, and checks one existing **private Shared Wall** via `GET /rest/v1/walls?select=id,type,visibility&id=eq.<uuid>`. Expected results: owner=1, accepted/allowed member=1, unrelated outsider=0. Positive rows must be exactly the requested Wall ID with `type='shared'` and `visibility='private'` to prevent a misconfigured Personal/public fixture producing a misleading security PASS. An HTTP 401/403 is **not** accepted as proof that an unrelated actor was denied (credentials must first work). Every API call is a GET (seven total: two per authorized actor plus one anonymous negative private-Wall GET); no user signup, OTP send, data write or feature switch occurs.

This is **not** a complete security suite: it does not test Personal Wall, friend/follower transitions, Mark RPC mutations, blocked/removed memberships, `INSERT RETURNING`, Secret, media, token refresh, offline, UX or physical-device behavior. Independent QA/Reviewer and the genuine broader 3-actor acceptance suite remain required.
